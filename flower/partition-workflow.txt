PARTITION WORKFLOW EXPLANATION
===============================

When you run `./run-partition-on-temp-vm.sh`:

1. VM Setup
-----------
- Creates or reuses temporary VM 'partition-tmp-vm'.
- Installs Python, gcloud SDK, and dependencies (numpy, matplotlib, seaborn).

2. File Transfer
----------------
- Copies partition scripts (`generate_partitions.py`, `partition-dataset.sh`) and config files (`.env`, `vm-info.txt`) to the VM.

3. Partition Generation (on temp VM)
------------------------------------
- Runs `generate_partitions.py` to calculate how data is divided.

   3a. Partitioning Algorithm (The "Partition First" Logic):
   ----------------------------------------------------------
   1. **Configuration**: 
      - Assigns each client a unique Dirichlet `alpha`.
      - Assigns each client a random "Target Train Cap" (between `min_train` and `max_train`).
   
   2. **Class-by-Class Distribution**:
      - For every class in COCO (e.g., "Dog", "Cat"):
        - **IID Client** (Client 0): Immediately takes a fixed 10% slice (1/N) to guarantee uniform distribution.
        - **Non-IID Clients** (1-9): Compete for the remaining 90% via Dirichlet lottery weights (alpha).
      - *Result*: Each client receives a raw "bag" of images. Some bags are large (rich clients), some are small (poor clients).

   3. **Splitting & Capping**:
      - The script looks at the ACTUAL number of images in each client's bag.
      - **Train Set**: Takes 66% of the bag, but strictly caps it at the "Target Train Cap".
      - **Validation Set**: Strictly sets it to **50% of the Training Set**.
      - **Discard**: Any excess images beyond these limits are discarded to maintain strict consistency.

   4. **Output**:
      - Generates `partition_manifest.json` (the master list).
      - Generates `client_plots/` to visualize class distributions.
      - Uploads everything to GCS bucket for backup.

4. Data Distribution (to Client VMs) via `partition-dataset.sh`
---------------------------------------------------------------
- Iterates through all 5 client VMs (processing 2 clients per VM).
- **Parallel Execution**: Sets up both clients on a VM simultaneously.

   4a. For Each Client:
   --------------------
   1. **Prepare**: Copies manifest to the VM.
   2. **Extract**: Reads the manifest to find exactly which images belong to this client.
   3. **Download**:
      - Uses `gsutil -m cp` (multi-threaded) to download only the assigned images.
      - Checks if images already exist to avoid re-downloading.
   4. **Download Labels**:
      - Checks for corresponding label files.
      - Downloads only the missing labels from GCS.
   5. **Verify**:
      - Counts final files on disk.
      - Compares strictly against the manifest values.
      - Fails if counts do not match exactly.

5. Finalization
---------------
- Reports successful distribution.
- The system is now ready for `deploy-application.sh`.
